# Prebuilt MCP servers

MCP (Model Context Protocol) servers enable AI models to safely and reliably interact with business applications and services. Workato offers prebuilt MCP servers through ready-to-use templates with tools that can be customized to fit specific workflows and requirements.

Prebuilt MCP servers are organized into the following categories:

- [Process MCP servers](#process-mcp-servers) complete a specific business process. These servers often connect multiple apps and use multi-step workflows.
- [Data and analytics MCP servers](#data-and-analytics-mcp-servers) transform, aggregate, and derive insights from data. These servers often connect multiple apps to analyze data across platforms.
- [App-specific MCP servers](#app-specific-mcp-servers) perform CRUD operations and access an app's foundational capabilities.

> **GETTING STARTED**
> 
> Get started with Workato MCP servers in [AI Hub > Enterprise MCP > Custom servers](https://app.workato.com/mcp/custom). Refer to the [Start with a prebuilt MCP server](/en/mcp/prebuilt-mcps) guide or a specific server's documentation for installation and configuration steps.

# Access Provisioning MCP server

The Access Provisioning MCP server enables LLMs to interact with Okta, Google Workspace, and Workbot for Slack for employee self-service access requests through natural conversation. It provides tools to request application access, follow up on a submitted request, and manage Google Group membership.

## Uses

Use the Access Provisioning MCP server to perform the following actions:

- Request access to an application in Okta or Google Workspace, with a business reason
- Follow up on a previously submitted request to see its approval and provisioning status
- Join a Google Group or distribution list
- Leave a Google Group or distribution list
- Look up who is a member of a Google Group

### Example prompts

Use the following example prompts to invoke Access Provisioning MCP server tools:

- `Can you get me access to Salesforce?`
- `Get me access to Workday.`
- `What happened to my Workday request from Tuesday?`
- `Is req_a1b2c3 done yet?`
- `Add me to the Marketing Google Group.`
- `Remove me from the eng-oncall group.`
- `Take me off the Marketing Google Group.`
- `Who's in the eng-oncall group?`
- `I need access to NetSuite for the Q3 close.`

## Access Provisioning MCP server tools

The Access Provisioning MCP server provides the following tools:

| Tool | Description |
| --- | --- |
| [provision\_app\_access](#provision-app-access-tool) | Requests application access for an employee and routes the request for approval before provisioning. |
| [get\_request\_status](#get-request-status-tool) | Looks up an access request by `request_id` and returns approval and provisioning status. |
| [check\_access\_status\_okta](#check-access-status-okta-tool) | Checks whether a specific Okta application is already assigned to a user (read-only). |
| [add\_user\_to\_group](#add-user-to-group-tool) | Adds an employee to a Google Group. |
| [remove\_user\_from\_group](#remove-user-from-group-tool) | Removes an employee from a Google Group. |
| [list\_group\_members](#list-group-members-tool) | Lists current members of a Google Group (read-only). |

## Install the Access Provisioning MCP server

Complete the following steps to install a prebuilt MCP server to your project:

1. Sign in to your Workato account.
   
2. Go to **AI Hub > Enterprise MCP > Custom servers**.
   
3. Click **\+ Create MCP server**.
   
4. Go to the **Start with pre-built MCP Servers using your connected apps** section and select the prebuilt MCP server you plan to use.
   
5. Click **Use this server**.
   
6. Provide a name for your MCP server in the **Server name** field.
   
7. Use the **Location** drop-down menu to select the project for the MCP server.
   
8. Go to the **Connections** section and connect to your app account.
   
9. Select the connection type you plan to use for the MCP server template.
   
   - **User's connection**: MCP server tools perform actions based on the identity and permissions of the user who connects to the application. Users authenticate with their own credentials to execute the skill.
   - **Your connection**: This option uses the connection established by the recipe builder and follows the same principles as normal app connections.
   
   ![Select your connection type](/assets/connection-type.Cor-6PJN.png)_Select your connection type_
   
   > **VERIFIED USER ACCESS AUTHENTICATION REQUIREMENTS**
   > 
   > Only app connections that use OAuth 2.0 authorization code grant are available for user's connection. Refer to [Verified user access](/en/mcp/verified-user-access) for more information.
   
10. Complete the app-specific connection setup steps in the following section.
    

## Access Provisioning connection setup

Configure the following connections to set up the Access Provisioning MCP server:

- [Okta](#okta-connection): Required if `enabled_systems` includes `okta`.
- [Google Workspace](#google-workspace-connection): Required if `enabled_systems` includes `google`, or to enable the Google Group membership tools.
- [Workbot for Slack](#workbot-for-slack-connection): Required. Dispatches approval cards and resolves approver identities.

### Access Provisioning role requirements

Each tool's availability depends on the permissions its connected account holds. Calling a tool without the required permission returns a `permission_denied` outcome rather than a partial result.

- **Okta** requires an API token generated by an Organization Administrator or Super Administrator. The token inherits that administrator's full permissions, since Okta API tokens don't support granular scopes. Refer to [Create an API token](https://developer.okta.com/docs/guides/create-an-api-token/create-the-token/) for more information.
  
- **Google Workspace** requires the scopes following at a minimum:
  
  - A service account with domain-wide delegation
  - The `admin.directory.group` scope
  - The `admin.directory.group.member` scope

Refer to the [Google Workspace Admin SDK authorization guide](https://developers.google.com/admin-sdk/directory/v1/guides/authorizing) for the complete list of scopes.

- **Workbot for Slack** requires the scopes following at a minimum:
  - `chat:write` to post approval cards
  - `users:read` to resolve approver identities

Refer to the [Workbot for Slack permissions reference](/en/workbot/workbot-for-slack-setup#permissions) for the complete list of scopes.

### Okta connection setup steps

View Okta connection setup steps

This deployment uses Okta's API key authentication method (an Okta API token). The token inherits the permissions of the administrator who generates it, since Okta API tokens don't support granular OAuth scopes the way Okta's authorization code grant and client credentials methods do.

#### Generate an API key

  

> **API KEY PRIVILEGES AND LIMITATIONS**
> 
> You must have administrator privileges in Okta to create an API key. Ensure that you're logged in as an administrator before you proceed.
> 
> Workato requires that the user and API key used in the connection have **Organization Administrator** or **Super Administrator** permissions. API keys inherit all permissions from the administrator who created them and can't be restricted to specific resources or operations.
> 
> Refer to [Create an API token](https://developer.okta.com/docs/guides/create-an-api-token/create-the-token/) for more information.

Complete the following steps to generate an API key in Okta:

#### Set up a Google service account

View Google service account setup steps

A Google service account is a specialized Google account associated with a Google Cloud Project (GCP) that can run API requests on your behalf.

Service accounts provide the following benefits:

- **Continuous operation:** Service accounts ensure that operations continue even if individual user permissions change.
- **Dedicated permissions:** Service accounts can only access projects that you share with them.
- **Dedicated API quotas:** You can manage a service account's API quotas through GCP and request quota increases directly from Google.

Refer to the [Google service account documentation](https://cloud.google.com/iam/docs/understanding-service-accounts) to learn more about service accounts.

Complete the following steps to set up a Google service account:

1. [Create a service account](https://cloud.google.com/iam/docs/creating-managing-service-accounts#creating) in your GCP project.
   
2. Go to **IAM & Admin > Service accounts**. Ensure your dashboard is scoped to the project that contains your service account.
   
   ![Check the scope of your dashboard.](/assets/service-project-scope.8Rf50DK2.png)_Check the scope of your dashboard._
   
3. Click the **Email** of the service account you intend to use.
   
   ![Click the email of the service account you intend to use.](/assets/service-email-button.C9qaZFkJ.png)_Click the **Email** of the service account you intend to use._
   
4. Copy the service account's **Email** and save it to configure your connection later.
   
   ![Copy the account's email](/assets/service-account-email.DM6BBBhN.png)_Copy the account's **Email**._
   
5. Go to the **KEYS** tab.
   
6. [Generate a private key](https://cloud.google.com/iam/docs/creating-managing-service-account-keys#creating_service_account_keys) and download it in JSON format. You can only download the key once.
   
7. Open the JSON file, then copy the entire private key from `-----BEGIN PRIVATE KEY-----` to `-----END PRIVATE KEY-----\n` (inclusive) and save it to configure your connection later.

### Configuration options

Use the following resources to configure the Access Provisioning MCP server:

- The [Server Configuration](#recipe-function-configuration) recipe function sets deployment-wide defaults.
- The [Application Access Config](#data-table-configuration) data table sets per-application approval routing.

#### Recipe function configuration

Edit the **Server Configuration** recipe function to configure the server's behavior:

| Key | Description |
| --- | --- |
| `enabled_systems` | Choose which identity systems this deployment provisions application access through. Defaults to `okta`. |
| `enabled_approval_channels` | Specify where to dispatch approval requests. Defaults to `slack`. |
| `group_directory_enabled` | Configure whether this deployment exposes the Google Group membership tools (`add_user_to_group`, `remove_user_from_group`, `list_group_members`). Defaults to `true`. |
| `admin_approver` | Required. Enter the default approver email or Slack handle for any application without a specific approver in the [Application Access Config](#data-table-configuration) data table. |
| `escalation_reminder_hours` | Enter the number of hours before a pending approval sends a reminder. Defaults to `24`. |
| `escalation_escalate_hours` | Enter the number of hours before a pending approval escalates to a secondary approver. Defaults to `48`. |
| `escalation_auto_deny_hours` | Enter the number of hours before the server automatically denies a pending approval. Defaults to `72`. |
| `max_justification_chars` | Enter the maximum number of characters a justification or reason field accepts. Defaults to `500`. |

View recipe function configuration steps

Complete the following steps to configure the Access Provisioning MCP server:

1. Sign in to your Workato account and go to **Projects**.
   
2. Go to the project that contains your MCP server.
   
3. Open the **Server Configuration** recipe.
   
4. Edit the value in the step for the setting you plan to change. For example, increase `escalation_auto_deny_hours` from `72` to `96`.
   
5. Save and start the recipe for the new value to take effect.
   

#### Data table configuration

Edit the **Application Access Config** data table to configure per-application approval settings:

| Column | Description |
| --- | --- |
| `data_source` | Enter the identity system the application belongs to: `okta` or `google`. |
| `application` | Enter the application name. |
| `application_id` | Enter the identity system's internal ID for the application. |
| `approver_emails` | Optional. Enter the approver for requests to this application. Defaults to `admin_approver`. |
| `enabled` | Configure whether `provision_app_access` can create a request for this application. An unmatched or disabled application returns `invalid_app`. |
| `auto_approve` | Configure whether a request for this application skips human approval and provisions immediately. |

View data table configuration steps

Complete the following steps to configure settings using the MCP's data table:

1. Sign in to your Workato account and go to **Projects**.
   
2. Go to the project that contains your MCP server.
   
3. Open the **Data Store** folder, then select the **Application Access Config** data table.
   
4. [Add](/en/data-tables/user-interface/edit#add-a-new-row) or [edit](/en/data-tables/user-interface/edit#edit-a-row) rows to make your changes. For example, add a row for a new application with `enabled` set to `true` and `auto_approve` set to `false`.
   

## How to use Access Provisioning MCP server tools

Refer to the following sections for detailed information on available tools.

### provision\_app\_access tool

The **provision\_app\_access** tool requests application access for an employee with the business reason you specify, then routes the request for approval. Your LLM uses this tool when you ask for access to an app. The tool resolves the identity system automatically if you don't specify one. It doesn't grant access itself; approval and provisioning happen separately.

**Try asking**:

- `Can you get me access to Salesforce?`
- `I need Tableau access for the Q3 close.`
- `Get me access to Workday.`
- `I need access to NetSuite for the finance close.`

### get\_request\_status tool

The **get\_request\_status** tool looks up an access request by `request_id` and returns its approval and provisioning status. Your LLM uses this tool when you ask about a request you already submitted.

**Try asking**:

- `What happened to my Workday request from Tuesday?`
- `Is req_a1b2c3 done yet?`
- `Check the status of my Salesforce request.`

### check\_access\_status\_okta tool

The **check\_access\_status\_okta** tool checks whether an Okta application is assigned to you. Your LLM uses this tool when you ask about your access. This tool is read-only.

**Try asking**:

- `Do I already have Salesforce access?`
- `Am I assigned to Workday in Okta?`
- `Check if I have Tableau access before you request it.`

### add\_user\_to\_group tool

The **add\_user\_to\_group** tool adds an employee to a Google Workspace group. Your LLM uses this tool when you ask to join a group.

**Try asking**:

- `Add me to the Marketing Google Group.`
- `I need to join the eng-oncall group.`
- `Request access to the finance-reports distribution list.`

### remove\_user\_from\_group tool

The **remove\_user\_from\_group** tool removes an employee from a Google Workspace group. Your LLM uses this tool when you ask to leave a group.

**Try asking**:

- `Remove me from the eng-oncall group.`
- `Take me off the Marketing Google Group.`
- `I'd like to leave the finance-reports distribution list.`

### list\_group\_members tool

The **list\_group\_members** tool lists current members of a Google Workspace group. Your LLM uses this tool when you ask who is in a specific group. This tool is read-only.

**Try asking**:

- `Who's in the eng-oncall group?`
- `Show me the members of the Marketing Google Group.`
- `Is Dana in the finance-reports distribution list?`
